# Study design as implemented

This is the methodology the code implements, item by item, with every
deviation from the planning document ("Coherence as a Reward: … under a
$1,100 Bedrock budget") and its reason. Configuration lives in `config/`;
nothing below is hard-coded elsewhere.

## 1. Data

| | DDXPlus | MedCaseReasoning |
|---|---|---|
| Source | figshare 22687585, md5-checked | HF `zou-lab/MedCaseReasoning` @ `469a5365…`, sha256-checked |
| Licence | CC BY 4.0 | MIT (dataset card) — the plan said CC BY 4.0 |
| Candidates | 49 pathologies, fixed alphabetical list, codes `AA`…`BW` | gold + 9 extracted distractors, order shuffled per case (seeded), codes `AA`…`AJ` |
| Unit of evidence | finding unit = parent question + its descriptors (pain + location/character/intensity…) | one atomic finding sentence (LLM-extracted, verified) |
| Exchangeability | chief complaint fixed first; symptom block, then antecedent block; units exchangeable within a block | chief complaint fixed first; findings exchangeable within a time class (0 history, 1 exam, 2 initial investigations, 3 later course) |
| Panel | 300 test cases: 6 per pathology × 49 + 6 random (all 49 pathologies covered) | 150 test cases (first 150 passing verification in a frozen seeded order) |
| Pilot | 20 disjoint test cases | 10 disjoint test cases |
| Extension (C2) | 300 further test cases | — |
| Training | train split, 8 held-out pathologies excluded (seeded draw per body system) | 2,000 train-split cases, gold never used in the label-free reward |

Selection filters: DDXPlus cases have 7–14 finding units and ≤ 34 tokens;
MedCaseReasoning case prompts 700–3,000 characters and 6–24 findings after
verification. Held-out pathologies: Acute laryngitis, Acute rhinosinusitis,
Boerhaave, Bronchiectasis, Chagas, PSVT, Panic attack, Sarcoidosis.

**Reference posterior (DDXPlus).** Corpus likelihoods `P(token|pathology)`
from the 1.03 M-patient training split (Jeffreys smoothing); posterior
`∝ π(d) Π P(t|d)^τ` over the presented findings, `τ = 0.6` chosen by minimum
NLL of the true pathology on training patients (top-1 0.98). Its JSD to the
released differentials (0.57) is reported, not used — those differentials are
far flatter than any positives-only posterior.

**MedCaseReasoning preprocessing** (paid, before the panel): GPT-6 Sol extracts
patient descriptor, atomic findings with paraphrase, time class, chief
complaint, diagnosis-leak flag, canonical diagnosis name and 9 distractors;
Claude Sonnet 5.5 (other vendor) verifies support, paraphrase equivalence,
leakage, stage, distractor validity. Finalisation is deterministic (rules in
`src/ccrl/prep/medcase.py`), runs before any panel call, and a rejected case
is replaced by the next in the frozen order.

**DDXPlus phrase bank** (paid, ~$1): one alternative wording per evidence
code (and per yes/no / special value), generated by the preprocessor,
verified by the verifier, then clinician-reviewed
(`artifacts/frozen/banks/phrasebank_review.csv`). Value meanings (body sites,
colours, 0–10 ratings, regions) are never reworded.

## 2. The ten calls per case

| # | transform | what changes | target | used in reward |
|---|---|---|---|---|
| 1 | base | seeded random order within blocks | — | (x) |
| 2–4 | perm1–3 | three more distinct orders, same set | posterior unchanged | yes |
| 5 | dup | one finding repeated later, "As noted above, …" | unchanged | yes |
| 6 | para | every finding in the frozen alternative wording | unchanged | yes |
| 7 | cue | one certified-irrelevant sentence inserted | unchanged | yes |
| 8 | authority | attending suggestion, stated 50 % reliability | log-odds shift = log(r(K−1)/(1−r)) | **no** (evaluation only) |
| 9 | ablate | one finding removed (DDXPlus: KB-informative, \|log LR\| ≥ log 2) | posterior moves, in the corpus direction | contrast option |
| 10 | retest | byte-identical to call 1 | noise floor | — |

The base order is random, not the release's code-sorted order: the previous
study (calibration C7) showed the grouped canonical order is systematically
easier and would contaminate the floor. Retest is a separate API call with the
identical request.

**Sequential arm** (150 DDXPlus cases, 7 models): the non-fixed findings are
split into halves E1/E2 (seeded); conversation A gives context + E1, then E2;
conversation B gives E2, then E1. Final posteriors are compared with each
other (commutativity) and with the one-shot base answer.

**Effort arm** (core 150: 75 + 75): calls base, perm1, para, cue, ablate,
retest at medium and high effort for Opus 5.5 and GPT-6 Sol.

**Pilot only:** an extra call with a 0–100 plausibility schema (key `s`) on the
base vignette, to test schema dependence (calibration C6 of the previous study).

## 3. Prompts and output

`config/prompts/`. DDXPlus: the 49-candidate list is in the system block
(identical for every DDXPlus request, above the 512-token cache minimum).
MedCaseReasoning: the case-specific list is in the user message. Required
output: one JSON object `{"dx": "<code>", "p": {"<code>": <int>, …}}`, integer
percentages over every code summing to 100. No reasoning is requested; any
reasoning or summary the API returns is archived. No temperature / top-p is
ever sent (Opus 5.5 rejects them; others run at provider default, recorded).
No fallback model: a refusal is recorded as a refusal.

Parsing (`src/ccrl/prompts/parse.py`): last JSON object with the key wins;
`<think>` blocks and fences stripped; sums renormalised; all-zero → uniform
(non-informative, not a failure); missing codes → 0 and counted; one fresh
retry on parse failure, one on truncation (2× max tokens), one on a timeout.

## 4. Estimands (`src/ccrl/analysis/estimands.py`)

Per (job, model, effort, dataset):

* **floor** = mean JS(base, retest); **ceiling** = mean JS between base
  posteriors of different patients (DDXPlus) or label-permutation ceiling
  `E_σ JS(q, σq)` (MedCaseReasoning, where between-patient JS is undefined
  because candidate lists differ — *deviation from the plan, which assumed a
  between-patient ceiling for both*).
* **NOE** = (mean JS(base, perm) − floor) / (ceiling − floor); same form for
  duplication, paraphrase, cue.
* **Evidence sensitivity** = share of cases with JS(base, ablate) above the
  model's 95th-percentile retest JS.
* **Direction agreement** (DDXPlus) = sign of the model's log-odds change for
  the gold diagnosis when the finding is removed vs the sign of the corpus
  log LR; and the same over the reference's top-5 diagnoses.
* **Authority exchange rate** = observed log-odds shift on the suggested
  diagnosis / normative shift.
* **Accuracy and calibration**: top-1, top-3, Brier, ECE (top-label);
  **knows-vs-states** = P(stated `dx` = gold) / P(argmax = gold).
* **Safeguards**: entropy, cross-patient information (DDXPlus).
* **Sequential**: JS(A_final, B_final) vs floor; JS(A_final, one-shot).

CIs: case-clustered bootstrap (2,000). Paired comparisons and
non-inferiority (Track B): `src/ccrl/analysis/stats.py`.

## 5. Spending controls

Ledger (`runs/ledger.sqlite`): every attempt with request, response, usage,
reported cost and conservative "guard" cost. A call is sent only if
committed spend + its worst-case reservation (input estimate at full price +
max tokens × output price, ×1.25 for unverified prices, no Flex discount)
stays under the hard cap ($1,000), the job cap and the per-model cap. Attempts
that timed out after sending stay counted at their reservation. No paid call
after 18 Dec 2026 23:59. Priority order enforced; priority C gated at $700 and
10 Dec. Frozen inputs hashed (`ccrl freeze`); paid jobs refuse to run on any
change.

## 6. Deviations from the planning document

| plan | implemented | why |
|---|---|---|
| MedCaseReasoning "CC-BY 4.0" | MIT | the dataset card at the pinned revision says MIT |
| between-patient ceiling everywhere | label-permutation ceiling for MedCaseReasoning | candidate lists differ per case |
| paraphrase = LLM rewrite per vignette | per-finding phrase bank (DDXPlus), per-finding verified paraphrase (MedCaseReasoning) | meaning preservation is checkable per finding; clinicians review ~230 rows, not 450 vignettes; same mechanism serves training |
| KB-Bayes = naive Bayes | tempered naive Bayes, τ = 0.6 by NLL | naive Bayes is over-confident; τ keeps Proposition 1 |
| reward contrast = single-finding ablation | triage contrast (chief complaint only); single ablation kept as eval + option | Finding 1 (docs/theory.md) |
| per-rollout sensitivity S | batch-level sensitivity gate; per-rollout form kept as ablation | Finding 2 |
| fidelity on single-finding log-odds | log-odds fidelity on the top-3 predicted diagnoses, stable direction | numerical stability at 0.5 % resolution |
| sensitivity without noise floor | floor-subtracted | Correction 1: noise would be rewarded |
| DDXPlus "2 symptom units" style filters | ≥ 7 units, no per-block minimum | otherwise Larygospasm has no eligible patient |
| effort arm: 6 calls | base, perm1, para, cue, ablate, retest | keeps a floor for normalisation |
| preprocessor = GPT-6 Sol | GPT-6 Sol + a different-vendor verifier (Sonnet 5.5) | cross-vendor check of extraction |
